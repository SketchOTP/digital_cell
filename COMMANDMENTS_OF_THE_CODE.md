# Engineering Principles

1. Make the smallest correct change.
2. Read existing behavior before changing it.
3. Reuse established project code and declared dependencies.
4. Keep behavior explicit, boring, and testable.
5. Preserve existing conventions unless the task requires a change.
6. Handle errors at their cause; do not silence failures.
7. Protect security, privacy, data integrity, and applicable accessibility boundaries.
8. Add focused validation for non-trivial behavior.
9. Avoid unrelated cleanup and speculative abstractions.
